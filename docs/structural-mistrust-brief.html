Structural Mistrust

I build trustworthy surfaces through one discipline: structural mistrust. Nothing freezes as settled until it survives disagreement, and the trust that produces is meant to be verified over time — earned, not asserted.

01 · opener

A trustworthy user surface is never settled.

Drift never stops pulling at it. The framework defends it on two tracks: a surface track (loud, fast — calibration drift, then process rot) and a silent track (slow, deep — doc drift, then discipline drift). The tracks are coupled: the surface only holds if the silent track underneath is intact.

Underneath all of it runs one cycle — the operator loop — and everything below is an artifact inside it.

One cycle under everything: author under mistrust → freeze the few → guard at runtime → surface catches → reconcile against outcomes → move the freeze line back, as outcomes earn trust. The reconcile-and-defrost half is designed, not yet running.
02 · class 1
calibration drift

Calibration drift

What.  Defends against outputs that overclaim their certainty. Most teams gate on a threshold and tune until it passes — which buries the failures that scored just under it.

How.

  • Gradient, not gate — every output ships with a confidence score computed from its own inputs: mechanical, not editorial.
  • Independent check — the validator is authored separately from the scorer, so the system never grades its own homework.

A low score is the system telling the truth about itself — worth more than a clean pass that hides its weak spots.

03 · class 2
process rot

Process rot

What.  Defends against erosion that still looks clean — the output passes, the metrics read fine, but the discipline producing them is decaying underneath.

How.

  • Failure is a valid ship state — when a check fails, ship it marked low with a revisit locked, never tune until it passes (which turns the eval adversarial to honesty).
  • Friction matched to blast radius — routine changes are easy; re-authoring a frozen judgment is hard, and a fork on a high-stakes decision is the signal the spec is too loose.

Decouple shipping from passing and the eval stays a real signal — there's nothing to fake, because faking buys nothing.

04 · class 3
documentation drift

Documentation drift

What.  The hidden twin of Class 1 — the same overclaim moved where you won't look: the record says the system is sound while the path underneath rots.

How.

  • Doc-vs-code — documentation is checked against deployed reality; when they disagree, the doc is wrong until proven otherwise.
  • Append-only audit — the record is superseded, never silently overwritten, so there's always a preserved trail to verify against.

It's the quietest failure because it covers for the others — and the preserved trail is the legitimacy floor of the whole framework.

05 · class 4
discipline drift

Discipline drift

What.  Decay moved out of sight — not the steps rotting, but the why behind them. The rule still gets followed, by rote, by people who no longer know what it protected against.

How.

  • Every rule carries its scar — the specific failure that made it necessary travels with the rule, so it can't hollow out.
  • The system surfaces its own history — recurrences and skipped rules get flagged; the seeing is mechanical and ports, the accountable call to reopen stays with me.

This is the floor. A forgotten why becomes a skipped step, becomes a fragile path, becomes an overclaim the user feels. Defended here, none of it starts.

06 · coupling

A system fails two ways — it can overclaim or it can erode.

fig 2 · canonicalcoupling map — the 2×2
Visibility × failure type. The silent row is the surface row hidden: doc drift is calibration drift concealed; discipline drift is process rot concealed. Process rot is the hub both links pass through.

A system fails two ways — it can overclaim (claim a confidence it hasn't earned) or erode (let the discipline behind its judgments decay) — and each happens where you see it or where you can't. The silent row is the surface row with the lights off: doc drift is calibration drift hidden, discipline drift is process rot hidden. Two paths run through process rot, the hub: the cascade (a forgotten why climbs into a skipped step, then an overclaim) and the conceal diagonal (the hidden overclaim covers for the surfaced rot).

07 · the engine

The judgment has to be authored well enough to freeze.

Before any of this guards a live surface, that authoring is design-time work. For decisions that come down to a pick from a short list, I run the same authoring decision across multiple model runs and count how often the answer forks; where the runs split is where judgment is load-bearing and a human should look before freezing. The freeze line itself is set by three readings — blast radius, trust, and cost to reopen — and it moves: as outcomes earn trust, a frozen decision defrosts back to the live model.

09 · honest limits

Built and defensible — but not yet validated by outcomes.

The over-time reconciliation is instrumented but hasn't accumulated enough reality to score against. So three parts — the outcome loop, Class 4's automated seeing, and the freeze line's defrost — are designed, not yet claimed as running.

10 · close

What's new isn't the parts.

Goodhart, error budgets, immutable logs are all borrowed. It's the stack: four classes, two tracks, and a freeze line that moves on outcomes, knitted into one operator loop, with room for a fifth class when one proves out.

The claim is small and exact: not that the system is correct, but that it's honest about what it knows — and instrumented to stay honest over time.
